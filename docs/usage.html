An introductory reference manual for scripting quantum emission runs inside the GETELEC architecture.

The 4-Block Simulation Pipeline

GETELEC avoids the rigid programmatic constraints of analytical emission formulas by breaking every simulation down into four distinct, independent structural components; allowing the user to tailor the simulation to the system of interest. GETELEC is built in such a way that transmission solver can be applied to arbitry potentials, band structures, and electron supplies. To initialize a calculation loop, you must initiate the instances of these sub-modules together inside a management interface:

Potential Barrier
Band Structure
Electron Supply
Transmission Solver

Once wrapped inside an executive manager (such as MetalEmitter or SemiconductorEmitter), the data arrays are processed concurrently using efficient matrix vector operations to run electron emission simulations. In a nustshell, the user should build an "Emitter" object (e.g.; MetalEmitter) by adding to it the elements that composes it (e.g.; SchottkyBarrier, SmartMetal, FermiDirac, Noumerov). Then, the Emitter object can be used to make serveral calculations such as the Nottingham Heat.

Within the GETELEC directory we have included modellic scripts to show the users how the Emitter objects are built and how they can be used to run simulations or to fit data. In the next section the script to calculate TED and NED is explained for clarity.

Show Case Example: Calculating Energy Distributions (TED & NED)

As an example of GETELEC's implementation to run calculations refer to the following folder inside the main directory.

🗀 File Context: examples/calculate_energy_distributions.py

This script instantiates a basic metallic emitter, extracts multi-variant spectral vectors, and plots comparative outputs simultaneously.

Review the standard application workflow model highlighted within the example folder:

import matplotlib.pyplot as plt
from getelec.potential_barrier import SchottkyPotential
from getelec.band_structure import SmartMetal
from getelec.transmission_solver import Noumerov
from getelec.electron_supply import FermiDirac, LogFermiDirac
from getelec.electron_emitter import MetalEmitter

# Initialize execution modules
my_potential = SchottkyPotential(fermi_level=7.5, work_function=4.5, electric_field=3.0)
my_band = SmartMetal(barrier_width=3.0, supply_threshold=1e-14, energy_resolution=0.01)
my_solver = Noumerov(x_metal=-1.0, x_vac_plus=10, h=0.001, max_barrier_width=3)
my_supply_log = LogFermiDirac(fermi_level=7.5, temperature=300.0)
my_supply = FermiDirac(fermi_level=7.5, temperature=300.0)

# Build the Emitter object
emitter = MetalEmitter(my_potential, my_solver, my_supply_log, my_band)

# Interrogate the object to extract the relevant information
energies, ned = emitter.calculate_normal_energy_distribution()

# Dynamically re-assign alternative distribution states (don't build another object!)
emitter.supply = my_supply

# Re-interrogate the object to extract the new relevant information
_, ted = emitter.calculate_total_energy_distribution()

Dynamic Parameter Broadcasters

Rather than forcing full model object reconstruction loops during large-scale operational sweeps, the parent emitter managers expose an explicit parameter broadcasting function: update_params(**kwargs).

Passing configuration keys directly down into the wrapper translates simplified variable naming descriptors, updates properties seamlessly inside lower-tier objects, and forces the framework to flush outdated array caches out of system memory automatically.
